## Commands

```bash
./start.sh                      # backend :8000 + frontend :3000 together (Ctrl+C stops both)

# Backend (from backend/)
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn main:app --reload --port 8000

# Frontend (from frontend/)
npm install
npm run dev                     # next dev
npm run build                   # next build --webpack
npm run lint                    # eslint
npm test                        # vitest run (every src/**/*.test.ts(x))
```

- `start.sh` and the README hardcode `.venv/bin/...` (POSIX layout); on Windows the venv uses `.venv\Scripts\` instead, so run the two servers manually. Verified on Windows: `py -3.12 -m venv .venv` (PyMuPDF wheels may not exist for the newest Python, e.g. 3.14), `.venv\Scripts\python.exe -m pip install -r requirements.txt`, `.venv\Scripts\python.exe -m uvicorn main:app --port 8000`.
- Always pass `encoding="utf-8"` when reading `demo_data/*.json` (Windows defaults to cp1252 and 500s on the Greek letters).
- `npm run build` and `npm run lint` both pass. The lint config enforces `react-hooks/set-state-in-effect`: don't call setState synchronously in an effect body (reset state in event handlers, or derive it from props/keys; do fetches inside the effect with a `cancelled` flag, as `page.tsx` does).
- The frontend reads the backend URL from `NEXT_PUBLIC_API_URL` (default `http://127.0.0.1:8000`); `src/api/client.ts` also accepts `NEXT_PUBLIC_API_BASE` as an alias.
- Frontend tests: `frontend/vitest.config.ts` runs every `src/**/*.test.ts(x)` in jsdom (setup file `src/tutor/test-setup.ts`). Put new tests next to the code they cover.
- `backend/.venv` was committed once and then deleted from the repo — never re-add it.
- **Next.js here is a newer major than most training data** (`next` 16.x, React 19, Tailwind 4, `cacheComponents`/`partialPrefetching` enabled in `next.config.ts`). `frontend/AGENTS.md` (auto-regenerated by `next dev`) says to read `frontend/node_modules/next/dist/docs/` before writing Next.js code.

## What is implemented today

**Backend** (`backend/main.py`, `backend/schemas.py`; Pydantic v2 models are the contract with the frontend):

- `GET /api/demo/{lecture|paper2sim|hypothesis}` — loads `backend/demo_data/*.json` into `WorkspaceDataset`. For `paper2sim` it overwrites the series with a live-computed heavy-ball/damped-oscillator sim (`run_heavy_ball_sim`).
- `POST /api/simulate` — re-runs that same hardcoded sim from slider params `gamma`, `eta`, `theta0`. **Not** LLM-generated code or a sandbox yet.
- `POST /api/ingest/pdf` (PyMuPDF; first lines of up to 6 pages become nodes) and `POST /api/ingest/url` (arXiv abstract via `export.arxiv.org`, falls back to canned chunks offline) — both feed `_build_graph_from_chunks`, which makes a heuristic chain graph with a templated quiz. For `paper2sim` mode it just retitles the demo dataset.
- `POST /api/ask-spatial` — **canned** per-mode answers keyed on `req.mode` / hit IDs; no LLM, no image use yet.

**Frontend** (`frontend/src/`; `DESIGN.md` is the full UI spec; shared types in `src/types/scholartwin.ts`):

- `app/page.tsx` switches the client screens `home | library | papersim-workspace | hypothesis-chat`. `app/lecture/lesson/page.tsx` is Live Lessons: lobby → call → recap, with `?track=<id>` preselecting a track (components in `src/tutor/shell/`).
- **Home:** `HomeHub` plus `components/home/*`: module cards with `ModuleArt` drawings, and a "Pick up where you left off" `RecentList` across all modules (`lib/recent.ts`).
- **Paper Simulator:** `LibraryView` (start screen: "Open a paper", "Your papers") and `PaperSimTabsView` (Simulate / Concepts / Results / Equations, `components/papersim/*`).
- **Evidence Map:** `HypothesisChatView` plus `components/hypothesis/*` (`TopicSidebar`, `Details`, `PaperList`); `initialTopicId` opens a saved topic.
- **Tutor:** `tutor/AskTutorButton.tsx` and `tutor/askTutor.ts` turn the paper or map on screen into a lesson track and open `/lecture/lesson?track=<id>`. The old tutor stack (`/tutor` page, `LiveTutorFab`, `LiveAvatarTile`, `useAvatarCall`, `InspectorPane`, `backend/app/modules/tutor`, `agent/avatar_agent.py`) is gone. Live Lessons (LiveKit + `agent/agent.py`) is the only tutor.
- **Module names vs ids:** visible names, descriptions, icons, hues and landscapes come from `src/modules.ts` (`MODULES`): `lecture` = **Live Lessons**, `paper2sim` = **Paper Simulator**, `hypothesis` = **Evidence Map**. The ids stay as internal keys (routes, storage, API modes); never show them as text.
- **Meadow Glass essentials** (`app/globals.css`, top comment):
  - Use tokens only: the moss/paper palette, plus `--status-support|contradict|gap|warning|link` (spruce teal / clay / heather / wheat / river, CVD-safe). Text that sits on the landscape uses `--on-scene*` / `--scene-glow` via `.on-scene`.
  - Each screen picks its painted landscape with `useScene(kind, calm)` (`components/nature/Scene.tsx` + `paint.ts`). It is off in high contrast and under reduced transparency.
  - `.glass-lens` is an opt-in refracting rim. It needs a positioned element; never put it on the same element as `st-sheen`.
  - Use `components/glass/Segmented.tsx` for tabs and switches.
  - There is no pointer-following light (removed on purpose).
  - Entrance animations use fill-mode `backwards`. Never leave a `filter` on glass.

## Intended architecture (summary of guide §3 and the Phase 2.0 recommended implementation)

Athena is **one unified 3-pane workspace**, not four separate apps. Every node/graphic can be *Explained* (avatar + Circle-to-Ask + quiz), *Simulated* (Paper2Sim), or *Fact-Checked* (HypothesisGraph).

- **Left pane:** Anam avatar, voice/mic controls, source uploader.
- **Center pane:** React Flow graph / Plotly sim plot / contradiction graph with a transparent `<canvas>`/SVG "Circle-to-Ask" lasso overlay.
- **Right pane:** context inspector (slide jump, adaptive quiz, generated simulation code, evidence/contradiction cards).

Recommended stack (Phase 2.0; swappable): Next.js + Tailwind + `@xyflow/react` + elkjs + Plotly + Pyodide (Web Worker) on the frontend; FastAPI + Pydantic v2 backend with PyMuPDF, Claude API (`anthropic` SDK, `claude-opus-5-5`), Semantic Scholar/OpenAlex/arXiv clients, and a Docker sandbox fallback.

Key rules and contracts to keep consistent when implementing:

- **LLM:** frontier model (Claude API) by default for everything. All extraction goes through an `Extractor` interface; a fine-tuned model is a **stretch goal** (Phase S) behind `EXTRACTOR_BACKEND=frontier|finetuned` with automatic fallback to frontier. Use structured outputs for JSON (no forced `tool_choice`, no prefill on Opus 5.5); set `output_config.effort` per route.
- **Tool access:** MCP connector only for remote MCPs that accept a static token and where the model should choose the call (Tavily; fal behind a flag). Custom Python tools for our own capabilities (paper search, sandbox). Direct APIs for deterministic, streaming or OAuth-only services (ElevenLabs STT/TTS, Anam tokens + JS SDK, Synthesia renders). Sponsor MCPs in Claude Code are dev-time only; the app uses its own keys from `.env`, never exposed to the browser.
- **Tool broker:** every runtime tool/LLM call goes through `tools/broker.py` (content-addressed cache, `OFFLINE=1` mode, per-route allow-lists and budgets, untrusted-content handling).
- **Graph JSON:** nodes `{id, kind: concept|claim|paper, label, summary, source_ref: {doc_id, page}}`, edges `{id, source, target, type: prerequisite|supports|contradicts|gap, condition, evidence[], confidence}`, plus `meta.extractor_used`. Colors: blue prerequisite, green supports, red contradicts, dashed gap. Prerequisite edges must have no cycles.
- **Paper2Sim:** generated code defines `PARAMS` (min/max/default/step/unit) and `simulate(**params) -> {title, x_label, y_label, series: [{name, x, y}]}`; runs primarily in Pyodide, with a Docker sandbox fallback (10s timeout, no network); one retry on a traceback or a failed validation.
- **Circle-to-Ask:** posts `{transcript, cropped_image_base64, hit_metadata, active_context}` to `POST /ask-spatial`; the response has `spoken_answer` plus `segments: [{text, ui_annotations}]` — the frontend speaks each segment and fires its annotations when it starts.
- **Demo Preset mode:** the frozen broker cache + media (audio, clips) loads the lecture, paper and 30–50 paper topic with no network. Hard requirement: no feature may depend on a live call without a cached fallback.

### Known drift: current code vs. guide contracts

The Phase-1 code predates the §3.3 contracts, so expect to migrate both sides together when wiring real LLM/sandbox paths:

- Endpoints live under `/api/...` (`/api/ask-spatial`), not bare `/ask-spatial`.
- `SpatialAskRequest` is `{mode, transcript, bbox, hit_node_ids, hit_edge_ids, sim_params, cropped_image_b64}`; the response is `{spoken_answer, avatar_state, annotations, suggested_quiz_node_id}` with annotation types `pulse_node | highlight_edge | callout_box` — no `segments`, no `active_context`.
- `GraphNode` uses `category` (`core|prerequisite|claim|paper|gap`) and `slide_ref`, plus layout `x`/`y`, `mastery` and embedded `quiz`; guide uses `kind` and `source_ref`. `GraphEdge` lacks `evidence[]`/`confidence`; node layout is server-supplied, not elkjs.
- `SimulationPayload` carries `python_code`/`params`/shared `x` with per-series `y`; guide's `simulate()` returns per-series `x, y`. Plotting is currently custom in `PaperSimCanvas`, not Plotly.
- No `tools/broker.py`, `Extractor` interface, `OFFLINE` flag or `.env` loading exist yet; the only "offline" behavior is the cached `demo_data/` JSON and the canned fallbacks in `/api/ingest/url`.
